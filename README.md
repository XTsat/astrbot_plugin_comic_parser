## 功能

- **贴链接就能下**：`/comic <作品链接>` 自动识别站点并下载整本，不用记每个平台各自的命令
- **按 ID 直接下载**：给出漫画 ID 或链接即可下载整本
- **在聊天里直接搜**：`/jm sou <关键词>` 只搜 JM，`/comic sou <关键词>` 一次搜所有支持搜索的渠道；每个渠道单独计时，某个渠道超时会自动跳过，不会让整条命令一直转。搜索词前可以加类型前缀（`tag:` 标签、`author:` 作者等），前缀前加 `-` 表示排除。结果按序号连续排列，每条只留标题、作者/页数与作品 ID，下载示例统一放在末尾；直接回序号就能下载（如 `/comic 1`、`/jm 1`）。结果多时分页展示，发 `/comic 下一页` 或 `/jm 下一页` 继续看（`上一页` 同理，也认 `next` / `prev`），编号跨页连续，搜索后 10 分钟内有效
- **E-Hentai 渠道**：`/eh <gid:token 或链接>`（全称 `/ehentai`）下载整本 E-Hentai 作品。不填 Cookie 时匿名下载 1280px 宽的重采样图；填了 Cookie 并开启「优先原图」后才取原图，原图按文件大小扣站点图片配额。站点配额按 IP 计算，用尽时本次下载会先停下并保留断点，重新发一次命令接着下，页数多的作品建议分几次下完
- **统一打包**：下载完成后统一打包为 ZIP 压缩包、PDF 文档或纵向长图，也可以只保存到本地不发送
- **统一加密**：全局只有一个打包密码，ZIP 用 AES 加密、PDF 用 AES-256 加密；设置了密码但没有安装加密依赖时会直接报错，不会悄悄发出未加密的文件
- **进度可见**：默认在命令消息上贴表情（❤️ 下载中 → OK 完成 / 🔨 失败），贴上了就不再发「开始下载」这类消息；也可切换为文本进度或关闭。进度每 15 秒刷新一次，慢网下一章拖几分钟也看得见，章节数与页数一起显示（如「1/2 章节 · 12/50 页」）
- **到点先停、下次接着下**：一次请求连下太久会先停下并保留已下好的图片，重新发一次同样的命令就从断点继续，已下好的页不再重下；断点会在设定时长后自动过期清理
- **结果说明可关**：下载完成的摘要（标题 / 作者 / 图片数 / 耗时）可以关掉，只发文件
- **会话管控**：白名单 / 黑名单决定哪些会话能用，防抖避免同一本被反复下载
- **先挑最快的域名**：多个站点域名 / 图床时，下载前会同时测一遍（响应时间 + 小样本下载速度），把最快的排到最前面，慢的不再让你干等；测速结果会缓存一段时间，不会每本都重测。探测超时、低速阈值与缓存时长都可调，也可以整个关掉
- **任务排队**：全局并发上限 + 整本超时与重试，多人同时使用时不会把机器拖垮；排队时会告诉你前面那本下到了哪、还要等多久
- **自动清理**：文件发出后删除本地临时文件，长期使用也不占满磁盘
- **下载完自动存进群文件的文件夹**：默认开启，成品传进当前群群文件里的目标文件夹（默认叫「漫画」）；群里没有这个文件夹时，机器人是管理员就自己建一个，建不了才放到群文件根目录；群里本来就会出现这条文件消息，聊天里不再重复发一遍，传不上去才改为直接发文件

### 搜索筛选

搜索词前可以加类型前缀，正向和排除（前缀前加 `-`）都支持：

- `tag:` 标签；`author:` 作者（也认 `artist:`）；`actor:` 登场角色（也认 `character:`）；`work:` 作品（也认 `title:`）；`parody:` 原作；`group:` 社团；`language:` 语言
- 中文前缀同样可用：`标签:`、`作者:`、`角色:`、`作品:`、`原作:`、`社团:`、`语言:`
- 前缀只认词首，大小写不敏感，半角/全角冒号都认；值含空格时用引号包起来，例如 `tag:"big breasts"`
- 前缀之外剩下的词仍按普通关键词搜索，所以可以「类型条件 + 关键词」一起用，例如 `/comic sou tag:巨乳 -tag:NTR 堕落`

支持范围：JM 支持 `tag` / `author` / `actor` / `work` 的原生筛选，E-Hentai 七个字段都能用原生语法筛选（`tag` / `work` 是裸词近似）；nhentai、哔咔、紳士漫畫、Hanime1 的上游搜索只收关键词，会按关键词搜索并在结果里标注，排除条件在这些渠道不生效。

JM 的字段搜索一次只能选一个域：同时带附加关键词、多个字段或跨字段排除时会改用综合搜索，并在结果里说明；E-Hentai 可以原生组合这些条件。

## 其它

### 常见问题

**为什么开了「下载后上传到群文件」，聊天里却还是收到了文件？** 两种情况会退回「直接发文件」：一是这次上传失败（原因会写在消息里），二是当前不是群聊下载或协议端不支持群文件上传。上传失败常见的原因是运行环境读不到这个文件——插件和协议端不在同一台机器、或不在同一份挂载目录里时，协议端拿不到插件的临时路径；另外机器人账号没有上传权限也会失败。

**下载到一半停了、消息说「再发一次接着下」是什么意思？** 一次请求连下太久（「单次连续下载时长」，默认 15 分钟）会先停下，图片留在临时目录里，所以这次不会打包发送；重新发一次同样的命令就从断点继续，已经下好的页不会重下，下完再正常打包交付。图片会在「断点保留时长」（默认 2 小时）后自动过期清掉，过期后再发就是从零开始；插件重载时如果开着「启动时清理临时目录」，断点也会被一起清掉。

**搜索时为什么有的渠道没出结果，或者提示超时？** 全渠道搜索给每个渠道单独计时（「搜索」里的「单渠道搜索超时」，默认 10 秒），某个渠道慢或被拦截时会被跳过，并在结果下方注明，其余渠道照常显示；调大超时或改用 `/jm sou` 这样的单渠道搜索即可。哔咔渠道搜索还需要先在渠道配置里填好账号密码，否则会直接提示需要账号。


**为什么文件进了群文件根目录，而不是配置的那个文件夹？** 群里没有这个文件夹、又没能新建时就是这样：新建群文件夹需要机器人是群管理员或群主，普通群成员建不了，插件会照样把文件传到根目录而不是让整次下载白费。把机器人设成管理员，或者手动在群文件里建好这个文件夹即可。
