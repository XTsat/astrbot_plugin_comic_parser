## 功能

- **贴链接就能下**：`/comic <作品链接>` 自动识别站点并下载整本，不用记每个平台各自的命令
- **按 ID 下载**：知道 ID 时用渠道命令（`/jm`、`/nh`、`/pica`、`/hm`、`/ssmh`、`/eh`）直接下那一本
- **在聊天里搜**：`/comic sou <关键词>` 一次搜所有支持搜索的渠道，`/jm sou` 只搜一个；结果回序号即可下载，多了按页翻
- **多个渠道**：JM、nhentai、哔咔、Hanime1、紳士漫畫、E-Hentai；E-Hentai 不填 Cookie 下 1280px 重采样图，填了才取原图（按站点配额扣）
- **统一打包**：下载完打包成 ZIP、PDF 或纵向长图，也可以只存本地不发送；单次下载想换格式在命令末尾加一句即可
- **打包加密**：设置一个打包密码即生效，ZIP 用 AES、PDF 用 AES-256
- **进度可见**：默认在命令消息上贴表情（下载中 → 完成 / 失败），也可切换为文本进度或关闭
- **到点先停、之后接着下**：一次请求连下太久会先停下并保留已下好的图，发 `/comic retry` 从断点继续
- **排队与限流**：全局并发上限加整本超时与重试，多人同时用不会把机器拖垮
- **会话管控**：白名单 / 黑名单决定哪些会话能用，防抖避免同一本被反复下载
- **先挑最快的域名**：多个站点域名或图床时，下载前自动挑最快的一个
- **下载完先发一张封面**（默认关闭）：每次成功单独发一张封面；需要时可打开「给封面打码」把露骨部位糊掉。开了打码时，封面若被平台拦下（群里看不到、日志报发送失败）会自动整张重糊一次再发
- **存进群文件**：成品传进当前群群文件的目标文件夹
- **漫画下载器面板**（插件详情页 →「漫画下载器面板」）：一个页面分五个标签——「打码测试」拖图或从渠道拉封面就能看露骨指数与检出框，换打码样式、块大小、外扩、整张阈值现场糊一遍；「模型下载」把权重按二次元检测 / 二次元分割 / 写实三个家族分开列（类别、大小、上游地址、许可、装没装、是不是当前档位），页面上选「下载线路」（自动 / 只走镜像 / 只走源站 / 自定义）就能下载、看进度、删除，连镜像都通不了时还能手动上传 `.onnx` 安装；「渠道测试」按 ID 或作品链接看元信息与封面；「状态」看运行时、已装权重与渠道启用情况；「设置」把插件配置摊成表单直接改（渠道模板仍在 AstrBot 设置页）
- **自动清理**：文件发出后删除本地临时文件

|------|------|------|
| `/comic <作品链接>` | 全部（受白名单/黑名单约束） | 贴作品页完整链接，自动识别站点并下载整本；末尾可以再跟一个打包格式 |
| `<渠道命令> <ID 或链接>` | 全部（受白名单/黑名单约束） | 只下本渠道这一本。渠道命令是 `/jm`、`/nh`、`/pica`、`/hm`、`/ssmh`、`/eh`（全称 `/jmcomic`、`/nhentai`、`/picacg`、`/hanime1`、`/wnacg`、`/ehentai`，也认 `/ha`、`/hanime`、`/wn`）；`/pica` 需先在渠道配置里填哔咔账号 |
| `/eh <gid:token 或链接>` | 全部（受白名单/黑名单约束） | E-Hentai 的作品 ID 是 gid 加 token 两段，只给数字会提示补全（匿名 1280px；填 Cookie 才下原图） |
| `/comic sou <关键词>` | 全部（受白名单/黑名单约束） | 一次搜所有支持搜索的渠道，结果按序号连续排列；支持 `tag:`、`author:` 等类型前缀与 `-` 排除 |
| `<渠道命令> sou <关键词>` | 全部（受白名单/黑名单约束） | 只搜该渠道；`sou` 也认 `search`、`搜索`、`搜` |
| `/comic <序号>`（`/<渠道命令> <序号>` 同理） | 全部（受白名单/黑名单约束） | 下载搜索结果里对应编号的那一本，按结果所属渠道走 |
| `/comic 下一页`（也认 `next`；上一页用 `上一页` 或 `prev`） | 全部（受白名单/黑名单约束） | 翻本会话最近一次搜索的结果页，编号跨页连续 |
| `<下载命令> <格式词>` | 全部（受白名单/黑名单约束） | 只给这一次指定打包格式，覆盖「打包格式」配置；可选 `zip` / `pdf` / `long_img` / `none`（仅本地保存不发送），也认中文 `压缩包` / `文档` / `长图` / `本地` |
| `/comic stop`（`/jm stop` 等渠道命令同理，也认 `取消`、`停止`） | 全部 | 取消本会话正在进行的下载，排队中的请求一并取消；已下好的图片保留，停稳后发 `/comic retry` 接着下。管理员可用 `/comic stop 全部` 取消所有会话 |
| `/comic status`（也认 `状态`、`队列`） | 全部（管理员可用 `/comic status 全部` 看所有会话） | 查看本会话在跑与排队中的请求：在跑的给实时进度、已下体积、已用时长，排队的给位次；只读，不打断任何下载 |
| `/comic retry`（也认 `重试`、`继续`） | 全部（受白名单/黑名单约束） | 接着下本会话最近一次那本，暂停、中断或失败后不用回去翻原命令；带格式词（如 `/comic retry zip`）只给这次重试换格式。只认 `/comic`。这条记录会存盘，插件重载后仍然记得 |
| `/漫画帮助` | 全部 | 查看当前可用渠道、打包格式、密码与进度提示设置 |
| `/漫画网站`（也认 `/comicsites`） | 全部 | 列出各渠道官网与作品页链接示意（ID 用 `<ID>` 占位），方便到站内找作品、找 ID |

- `/comic` 只认完整链接（带域名的作品页地址）或搜索结果序号：裸 ID 和哔咔 App 的 `pica://` 分享内容无法判断站点，改用对应的渠道命令。渠道命令也不限定站点——`/jm` 后面贴 nhentai 链接下的是 nhentai 那本，实际走的站点写在下载摘要里。
- 缩写（`/jm`、`/nh`、`/pica`、`/hm`、`/ssmh`、`/eh`）是日常用法，插件提示里展示的也是缩写；站点全称一样能敲，效果相同。
- 格式词放命令最后：`/jm 123456 pdf`、`/comic <链接> long_img`、`/jm 1 none`。它只对这一次生效，配置不会被改；用 `sou` 搜索时，末尾的词仍算关键词。
- 搜索结果每条只显示标题、作者/页数、连续编号与 ID，下载示例统一放在末尾：发 `/comic 1`（或 `/jm 1`）就下载第 1 条。重新搜索会替换编号，序号在搜索后 10 分钟内有效；结果超过一页时末尾给出「下一页：/jm 下一页」，翻页优先用已取回的结果、翻完才去上游取下一页，编号跨页连续。
- E-Hentai 的作品 ID 由 gid 和 token 两段组成（如 `4306312:0123456789`），`gid:token`、`gid/token`、`gid-token` 都认，结尾多一个 `/` 也可以，直接从浏览器地址栏复制作品页链接最省事。不知道 ID 去哪找就发 `/漫画网站` 看各站点的作品页链接示意（`<ID>` 占位）。搜索结果不保证一定能下载（可能需要登录、已下架或受区域限制）。

示例：

```
/comic https://nhentai.net/g/123456/      # 贴链接最省事，站点自动识别
/jm https://18comic.vip/album/123456/     # 渠道命令也认链接
/jm 123456                                # 也可以只给 ID
/comic sou 触手                           # 搜所有支持搜索的渠道
/jm sou tag:"big breasts" -tag:NTR        # 只搜一个渠道 + 类型筛选
/comic 1                                  # 回序号下载第 1 条
/jm 下一页                                # 翻结果页
/jm 123456 pdf                            # 这一次导出 PDF，配置不变
```

### 搜索筛选

搜索词前可以加类型前缀，正向和排除（前缀前加 `-`）都支持：

- `tag:` 标签；`author:` 作者（也认 `artist:`）；`actor:` 登场角色（也认 `character:`）；`work:` 作品（也认 `title:`）；`parody:` 原作；`group:` 社团；`language:` 语言
- 中文前缀同样可用：`标签:`、`作者:`、`角色:`、`作品:`、`原作:`、`社团:`、`语言:`
- 前缀只认词首，大小写不敏感，半角/全角冒号都认；值含空格时用引号包起来，例如 `tag:"big breasts"`
- 前缀之外剩下的词仍按普通关键词搜索，所以可以「类型条件 + 关键词」一起用，例如 `/comic sou tag:巨乳 -tag:NTR 堕落`

支持范围：JM 支持 `tag` / `author` / `actor` / `work` 的原生筛选，E-Hentai 七个字段都能用原生语法筛选（`tag` / `work` 是裸词近似）；nhentai、哔咔、紳士漫畫、Hanime1 的上游搜索只收关键词，会按关键词搜索并在结果里标注，排除条件在这些渠道不生效。

JM 的字段搜索一次只能选一个域：同时带附加关键词、多个字段或跨字段排除时会改用综合搜索，并在结果里说明；E-Hentai 可以原生组合这些条件。

### 封面与 NSFW 检测的前提

封面打码与露骨度依赖本地 YOLO 检测模型，现在可选两家的权重：

- 写实档基于 [EraX-NSFW-V1.0](https://huggingface.co/erax-ai/EraX-NSFW-V1.0)（Apache-2.0 协议，类别为 anus / make_love / nipple / penis / vagina）的 nano / small / medium 三档；
- 二次元检测档基于 [deepghs/anime_censor_detection](https://huggingface.co/deepghs/anime_censor_detection)（仓库标注 MIT 协议，类别为 nipple_f / penis / pussy）；
- 二次元分割档基于 [01miku/anime-nsfw-segm-yolo26](https://huggingface.co/01miku/anime-nsfw-segm-yolo26)（仓库标注 MIT，权重内部标注 Ultralytics AGPL-3.0，与我们自己导出的写实 ONNX 情况相同），7 个类别，框更贴边。

**插件用的是这套权重的 ONNX 版本**——由我们从上游 `.pt` 导出（固定 960 输入、opset 17），int8 档另外做过量化，因此和上游原始文件不是同一份。上游仓库只提供 `.pt`，**插件不支持 `.pt`，请不要从上游直接下载来用**。

取权重有三条路，都不用改配置：

1. **面板里点下载**（推荐）：打开「漫画下载器面板 → 模型下载」，先选「下载线路」——**自动**（各档默认源）、**只走镜像**（国内直连不通时）、**只走源站**（境外网络）或**自定义地址**（填一次地址，只对本次下载生效，支持 `{filename}` 占位、可填多行），再点哪一档的「下载」。
2. **自动补装**：在「封面与模型 → 模型与检测」里打开「缺失时自动下载权重」，插件加载时自己拉当前档位（写实档走 GitHub 直连 + 内置加速镜像，二次元档走 HuggingFace 镜像再退回源站）。
3. **手动安装**：服务器连镜像都不通、或你有自己导出的 ONNX 时，在「模型下载 → 手动上传权重」里选文件、选它对应的档位安装即可（最大 256MB）；也可以把 `.onnx` 直接放进插件目录的 `models/`。检测运行时只依赖 `onnxruntime`（约 100MB）。它**不随插件安装**：只要开着「下载完成后发送封面」和「给封面打码」，插件每次加载/重载都会检查一次，缺了就在后台自动装上；装完重载插件即可用。装不上（容器没网、pip 不可用）时插件照常下载发文件，只是不发封面，可手动 `pip install onnxruntime`。

调参可以直接用插件详情页里的「漫画下载器面板」：在「打码测试」里拖图或从渠道拉一张封面，就能看到这套模型给多少分、框在哪、不同样式糊出来什么样，阈值与参数现场可调，不用真下一本来试；缺哪个档位的权重去「模型下载」页装（沿用这里的下载源与代理设置）。

要注意权重是放在**插件目录**的 `models/` 下的：把插件卸载、或从市场覆盖更新时，它们会跟着插件目录一起被清掉，需要重新下载。

打码默认关闭，所以不配模型也能收封面（原样发送，也不做检测、不写露骨度）。打开「给封面打码」后就必须有模型：权重不在位或检测失败时**那张封面不发**并提示，绝不放未打码的图出去。「缺失时自动下载权重」默认开启，在「下载完成后发送封面」与「给封面打码」都开着时由插件在加载/重载后台下载；也可以手动把 `.onnx` 放进 `models/`。

### 常见问题

**为什么开了「上传到群文件」，聊天里还是收到了文件，或者文件进了根目录？** 上传失败时插件会把错误贴出来，但有两类原因它自己判断不了：一是协议端读不到插件的临时文件——插件和协议端不在同一台机器、或不在同一份挂载目录时，那个路径对协议端并不存在；二是机器人账号没有上传权限，或群里还没有目标文件夹而又建不了（建群文件文件夹要求机器人是管理员或群主）。这时会退回「直接发文件」或传到群文件根目录，免得整次下载白费。让协议端能读到插件的临时目录、给机器人管理员权限，或在群里手动建好「漫画」文件夹即可。

**JM 搜索老是超时？** JM 的搜索接口直连有时要 10–20 秒，而「单渠道搜索超时」默认只等 10 秒。已经配了全局代理的话，到 JM 渠道配置里打开「使用代理」，实测约 1–3 秒；也可以把「单渠道搜索超时」调到 15–20 秒，或改用 `/jm sou` 只搜这一个渠道。

**封面打码糊得太多，或者反而露了？** 范围由「检测阈值」与「整张打码的面积阈值」共同决定：还露着就调低「检测阈值」、加大「打码框外扩像素」，或调小「整张打码的面积阈值」（更容易整张打码）；糊太多就往反方向调，样式也可以换成高斯模糊或黑条。整张全糊多是检出区域确实覆盖了大半张图（阈值默认 0.3，调到 0.6/0.8 更克制，设 0 关掉整张兜底）；完全没打码多是模型没检出——漫画页置信度普遍低，可把「检测阈值」降到 0.02。打开「单独发送封面说明」后，每张封面的说明里都写着这次的露骨度、检出数与覆盖比例、判定用的阈值，调参时对着这些数看最准。**群里始终看不到封面、日志里却有发送失败**时，是平台把这张图判成露骨图直接丢弃了：插件会自动整张重糊再发一次，仍发不出去就只能跳过这张封面（文件照常发送）。
