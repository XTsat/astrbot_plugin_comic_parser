# CHANGELOG 格式细则

> 本文件是 [`../AGENTS.md`](../AGENTS.md) 的细则页：`CHANGELOG.md` 的分组格式、加粗规则、破坏性变更标记与老版本折叠形态。
> 不在自动注入范围内，需要时用 `read` 打开。本文件上限 10 KB。

---

#### 格式

统一使用 **分组式**（与 scaffold 的 `CHANGELOG.md.template` 一致）：按分类用 `###` 子标题分组，条目用「标题 + 冒号 + 说明」，**仅重点条目/重点内容才加粗**：

```markdown
# Changelog

## [Unreleased]

> 一句话总结这个版本（可选）

### 新增
- 功能 A：说明
- **功能 B**：说明

### 修复
- 问题 C：说明

## v0.3.0 (2026-07-06)

> 一句话总结这个版本（可选）

### 新增
- 功能 D：说明
```

分组子标题分类：`新增` / `修复` / `变更` / `移除` / `性能`（只保留本次有内容的分类，无内容的分类不写空标题）

**加粗规则**：条目默认不加粗；写 changelog 时先识别本次改动中的**重点改动**（核心新功能、重要修复、破坏性变更等），只对重点改动用 `**加粗**` 标题强调，其余条目一律不加粗。

**版本总结**：版本标题（`## [Unreleased]` / `## vX.Y.Z (YYYY-MM-DD)`）与分类子标题之间，可加一行 `> 引用` 形式的一句话总结（概括该版本/该批改动的主旨），可选，不强制。

**破坏性变更标记**：含不兼容改动的版本段（删了上一版已有的功能、配置项改名、行为变更导致用户必须重配或迁移），在版本标题下紧接一行 `> ⚠️ 破坏性变更：<一句话说明改了什么、用户要做什么>`。这行标记不是装饰——它决定该版本段**永不折叠**（见下方「老版本折叠」），也是用户判断「要不要仔细看这一版」的入口。

**老版本折叠（按版本段数量，不按日期）**：CHANGELOG 在插件详情页与 GitHub 都是整篇渲染，版本段攒到十几个以后，用户要滚很久才看到「上一版」的差异。阈值按**版本段数量**判定而非日期：按日期会让长期停更的项目永远全展开、高频发版的项目把刚发的版本也折掉；按数量则每次发版只多折一个版本段，动作固定、结果可预测。

- **展开区**：`## [Unreleased]` 与**最近 3 个**已发布版本段。取 3 是因为用户回查的几乎都是「这版和上版差什么」「上上版改了什么」，3 个版本段已覆盖近几个月的更新；更早的属于考古，折叠不影响使用。
- **折叠区从第 4 个版本段开始，每个版本段各自一个 `<details>`**——**不是**把所有老版本塞进同一个 `<details>`。全塞一个块的话 summary 只剩一个标题，用户想找某个具体版本还得逐层展开、逐段扫，等于把「折叠」做成了「藏起来」。
- **与展开区之间要有明显分隔**：第一个折叠版本段之前插一行 `---` 水平线 + 一行说明文字（见下方形态），让人一眼看出「上面是近期、下面是历史」，而不是读完 v0.2.0 突然撞上一个折叠块。分隔只加一次，不在每个版本段之间重复。
- **破坏性变更的版本永不折叠，且保持整段完整**：只要该版本段带 `> ⚠️ 破坏性变更` 标记（或含 `### 移除`），无论多老都保持 `##` 标题展开、不包进 `<details>`，且标题下带 `⚠️`。**是整段展开，不是只挑破坏性那几条展开、其余折进去**——用户判断的是「这一版整体要不要小心」，同一版本里的破坏性条目常与旁边的条目联动（配置项改名 + 迁移提示），拆到两处反而要展开两次；拆开还要每次发版主观判断「哪几条算破坏性」，规则会执行不一致。代价可接受：破坏性变更本就罕见，一个版本段通常也只有十几行。位置仍按版本号倒序，所以折叠区里可能夹着一个展开的破坏性变更版本——这是刻意的，大改动就该显眼。
- **`<summary>` 自解释**：版本号 + 日期 + 该版本的一句话总结，例如 `<summary>v0.2.0 (2026-05-01) — 支持消息转发</summary>`；summary 里不写「点击展开」这类废话（分隔说明里已交代一次）。
- **折叠是发版动作**：把 `[Unreleased]` 落成新版本段时顺手折，见上方「流程」；日常提交不动折叠结构。
- **只折叠不删改**：折叠只是收起，不删版本段、不改条目文字；也不要把 `[Unreleased]`、最近 3 个版本或破坏性变更版本折起来图省事。

形态（`---` 分隔 + 说明行只出现一次，之后每个历史版本各自一个 `<details>`；破坏性变更版本保持展开）：

```markdown
## v0.4.0 (2026-08-01)
...

## v0.3.0 (2026-07-06)
...

## v0.2.0 (2026-06-01)
...

---

**以下为更早的历史版本（点击展开）**

<details>
<summary>v0.1.1 (2026-05-15) — 修复转发失败后不重试</summary>

### 修复
- 修复超时后不再重试、消息被静默丢弃的问题

</details>

<details>
<summary>v0.1.0 (2026-05-01) — 首个版本</summary>

### 新增
- 转发图片到其它群（`forward_image`）：开启后图片自动跟转到指定群聊

</details>

## v0.0.9 (2026-04-10)

> ⚠️ 破坏性变更：`forward_to` 改名为 `forward_targets`，升级后需重新配置

### 变更
- 转发目标配置项改名，升级后需在 WebUI 重新填写
```

> **折叠在 WebUI 会降级**：与 README 配置表的折叠同一套渲染（见 7.2.3），AstrBot 插件详情页内嵌渲染会过滤 `details` / `summary`，折叠块在那里变成普通文字、版本段照常显示——所以折叠只是缩短首屏，不能当成隐藏信息的手段；破坏性变更永不折叠也正是为了在这种降级场景下不漏掉大改动。
